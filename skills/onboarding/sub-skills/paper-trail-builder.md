# DevAgent Sub-skill: Paper Trail Builder
**Parent:** Onboarding — Sub-phase F
**Output:** `docs/Plan.md`, `docs/design/DesignIndex.md`, design doc stubs, maintenance queue entries

---

## Purpose

Reconstruct the planning and design artifacts from the confirmed PRD and codebase.
Produces a Plan.md that accurately reflects what's done vs what remains, and
design documents that reflect the actual architecture — not an idealized one.

---

## Subagent F1 — Plan.md Reconstruction

### Inputs
- `docs/PRD.md` (confirmed, with AS-BUILT / PARTIAL / PLANNED status per feature)
- `docs/design/TechnologyStack.md` (if written by F2)
- Detection report

### Procedure

**Step 1 — Task generation**

For each feature in PRD.md, generate tasks following Planning SKILL.md conventions:
- One task per logical unit of work (not too granular, not too broad)
- Use the same task type taxonomy from the active profile (web or macOS) if applicable
- Assign `TASK-XXX` IDs

**Step 2 — Status assignment**

| Feature status | Task status rule |
|---------------|-----------------|
| `AS-BUILT` | All tasks → `DONE` |
| `PARTIAL` | Tasks for existing code → `DONE`; tasks for missing parts → `TODO` |
| `PLANNED` | All tasks → `TODO` |

For PARTIAL features: split tasks clearly at the boundary of what exists.
Example: if a feature has UI but no backend → "Implement UI" = DONE, "Implement API handler" = TODO.

**Step 3 — Dependency mapping**

Map task dependencies using feature dependencies from PRD.md.
DONE tasks never depend on TODO tasks (would indicate a gap — flag if found).

**Step 4 — Effort estimation**

For TODO tasks only — estimate S/M/L/XL using the same criteria as Planning skill.
DONE tasks get actual effort marked as `[completed]` — no re-estimation needed.

### Plan.md format

Follow Planning SKILL.md structure exactly, with one addition — an onboarding header:

```markdown
# Plan.md
## Generated by: Project Onboarding — {date}
## Baseline: {X} tasks DONE (as-built), {Y} tasks TODO (remaining)
---
```

Mark each DONE task visibly:
```markdown
| TASK-001 | Implement login UI | DONE | [completed] | FEAT-001 | — |
| TASK-002 | Implement auth API | TODO | M | FEAT-001 | TASK-001 |
```

Write to: `docs/Plan.md`

## Subagent F2 — Design Index Reconstruction

### Inputs
- `docs/PRD.md` (confirmed)
- Detection report (architecture, stack, source locations)
- User interview (any design docs or references mentioned)
- Component analysis files

### Standard design documents — write or stub

For each document, apply this rule:
- **Write it** if enough information exists from code analysis + detection
- **Create stub** if information is insufficient — mark `[NEEDS DETAIL]`
- **Skip** if clearly not applicable to this project type

| Document | Write if | Stub if | Skip if |
|----------|---------|---------|---------|
| `TechnologyStack.md` | Always — detection is reliable | — | — |
| `SystemArchitecture.md` | Architecture pattern detected with HIGH confidence | MEDIUM or LOW confidence | — |
| `ComponentDesign.md` | Components clearly mapped from analysis | Partial mapping | Frontend-less project |
| `APIContracts.md` | API routes detected | Partial routes | No API |
| `DatabaseSchema.md` | Schema files / migrations found | Models found but no schema | No database |
| `SwiftUIDesign.md` | — | Always stub — design tokens need human input | Non-macOS project |
| `UIDesign.md` | — | Always stub — design tokens need human input | Non-web project |
| `EntitlementsDesign.md` | `.entitlements` file found | — | Non-macOS project |
| `PrivacyManifest.md` | `PrivacyInfo.xcprivacy` found | Capabilities detected | Non-macOS project |
| `RoutingDesign.md` | Routes file found | Partial routing | No routing |
| `DeploymentDesign.md` | Deployment config found | — | No deployment config |

### TechnologyStack.md (always written)

```markdown
# Technology Stack
## Generated by: Project Onboarding — {date}
## Source: Detected from project files

| Layer | Technology | Version | Notes |
|-------|-----------|---------|-------|
| Language | {detected} | {from manifest} | |
| Framework | {detected} | {from manifest} | |
| Build system | {detected} | | |
| Test framework | {detected or "None found"} | | |
| Database | {detected or "None"} | | |
| Deployment | {detected or "Unknown"} | | |
| Key dependencies | {from manifest top 5} | | |
```

### Stub format (for [NEEDS DETAIL] documents)

```markdown
# {Document Name}
## Status: [NEEDS DETAIL] — reconstructed stub
## Generated by: Project Onboarding — {date}
## What's known (from code analysis):
{bullet list of what was detected}

## What needs to be filled in:
{bullet list of missing information}

## Instructions:
Run the Design skill on this project to flesh out this document.
Or fill in manually and remove the [NEEDS DETAIL] marker.
```

### DesignIndex.md

```markdown
# Design Index
## Generated by: Project Onboarding — {date}

| Document | Status | Notes |
|----------|--------|-------|
| TechnologyStack.md | WRITTEN | Detected from project files |
| SystemArchitecture.md | WRITTEN | Reconstructed from code patterns |
| ComponentDesign.md | [NEEDS DETAIL] | Partial — run Design skill to complete |
| SwiftUIDesign.md | [NEEDS DETAIL] | Stub — design tokens require human input |
| ... | | |
```

Write to: `docs/design/DesignIndex.md` and all individual design docs.

## Maintenance Queue Population

If quality observations or known bugs exist (from component analysis or user interview):
Write each item to `.claude/skills/state/maintenance/input-queue.md`:

```markdown
# Maintenance Input Queue
## Populated by: Project Onboarding — {date}

| ID | Description | Severity | Source | Feature |
|----|-------------|---------|--------|---------|
| BUG-001 | Force unwrap in AuthViewModel.swift:42 | LOW | Code analysis | FEAT-002 |
| BUG-002 | Missing error handling in API calls | MEDIUM | Code analysis | FEAT-003 |
| BUG-003 | {user-reported bug} | HIGH | User interview | FEAT-001 |
```

Severity rules:
- **CRITICAL** — crash, data loss, security vulnerability
- **HIGH** — feature broken, user-reported bug
- **MEDIUM** — missing error handling, degraded behavior
- **LOW** — code quality issue, tech debt, TODO comment
